# Arcana · 手势塔罗

一套零构建的三张 Rider–Waite–Smith 塔罗牌前端交互原型。牌面来自完整 78 张牌库，支持摄像头手势、鼠标、触摸与键盘操作；每次牌阵依次锁定「来处 / 此刻 / 去向」三张牌。

## 启动

页面不需要安装 npm 依赖。只使用鼠标、触摸或键盘时，可以直接双击 `index.html`；完整 78 张牌面已经随项目提供，不联网也能显示。由于浏览器会限制本地 ES Module，WebGL 灰烬在 `file://` 下会立即使用 CSS 降级，不会等待网络模块。

要启用摄像头手势，推荐在项目目录运行本地 HTTP 服务：

```powershell
# 在克隆或下载的项目根目录执行
python -m http.server 4173
```

然后访问 `http://localhost:4173`。摄像头通常要求 HTTPS 或 `localhost` 安全上下文，直接使用 `file://` 打开时可能无法授权。

项目已本地附带固定版本的 MediaPipe Tasks Vision `0.10.35`、对应 WASM 与 Hand Landmarker 模型；通过 localhost 启用手势时会优先使用这些本地资源，失败后才尝试 CDN。视频帧只在浏览器本机用于手部关键点识别，不会上传或保存。

## 静态部署

这是零构建的 HTML / CSS / JavaScript 项目，无需运行 `npm install` 或构建命令。静态托管的入口为根目录 `index.html`，发布目录为项目根目录；保留所有根目录运行文件、`assets/` 和 `vendor/` 的相对位置即可。托管服务需要正确提供 JavaScript 模块和 `.wasm` 文件，并启用 HTTPS，手机浏览器才能申请摄像头权限。

将代码推送到 GitHub 仓库不等于已发布可访问的网站；仍需在选用的静态托管服务中配置该仓库与发布目录。项目没有后端或服务器端密钥，图像与识别资源优先从同站点加载，缺失时才按代码中的候选地址回退。

本地 `cloudflare-upload/` 是重复的手动上传副本，不纳入 Git；从仓库部署时直接使用根目录文件。请勿将 `.env`、账号凭据、本地工具配置或临时测试文件放入发布内容。

## 78 张牌库与随机规则

`deck.js` 建立完整牌库：22 张大阿尔卡那逐张定义，56 张小阿尔卡那由权杖、圣杯、宝剑、星币四个牌组与 14 个点数组合生成。每张牌都包含稳定 ID、中文及英文名称、正位和逆位两套关键词与解释文本。

- 底部牌带由 12 张语义牌背和一组视觉循环副本组成，只作为射线命中目标，不预先对应某张真实牌。
- 有效 PINCH、鼠标点击或键盘抓取发生时，程序才从尚未确认的牌库中等概率随机选择一张牌。
- 同时以 `Math.random() < 0.5` 冻结为逆位或正位。逆位牌面绕 Z 轴旋转 180°，外部的「逆位」标签与解释仍保持正向可读。
- 抓取后的牌处于待确认状态，尚未从牌库移除；选择「放回牌库」不会消耗它。
- 只有 FIST 或等价确认操作才会把牌从剩余牌库移除，并把牌名、正逆位、对应含义和确认时间写入历史。
- 同一轮三张牌不会重复。确认三张后生成牌面手记；撤回会把最后一张放回牌库，开始新牌局会恢复全部 78 张。

## 手势状态机

正常流程为：

```text
idle → armed → pulling → preview → committing → ashing → idle / complete
                             └→ returning → idle（取消）
```

| 手势 | 生效阶段 | 行为 |
| --- | --- | --- |
| `OPEN` 张掌 | `idle` / `armed` | 稳定约 180ms 后进入 `armed`；射线命中牌背时牌带暂停、目标牌悬浮，持续张掌会刷新允许时间。 |
| `PINCH` 捏合 | `armed` | 射线需稳定命中同一牌背约 80ms，再稳定捏合约 140ms；随后随机生成牌面与正逆位，先以牌背拉近，待约 420ms 动画与牌面加载等待结束后进入 `preview`。 |
| `FIST` 握拳 | `preview` | 预览出现后，以约 360ms 的有效强握拳证据确认并锁定结果；短于 160ms 的分类抖动只暂停、不清空进度，450ms 内重新握紧可继续。其他阶段的 FIST 不生效。 |

抓牌前以 `PINCH` 为最高优先级；进入 `preview` 后，至少三指明显弯曲且食指弯曲的强 `FIST` 会优先于残留的捏合锁存。确认进度只累计前后两帧均为强握拳的时间，短暂的 `PINCH / NEUTRAL` 抖动及关键点遮挡不会增加进度，也不会立即归零；重新稳定两帧后才会继续累计，间歇性的单帧拳头脉冲无法凑满确认。单独伸出食指会回退为 `NEUTRAL`，不会命中、高亮或暂停牌带。手部短暂离开画面会隐藏射线；待确认牌与历史不会因摄像头关闭、权限拒绝或识别中断而丢失。

页面准星的横纵坐标始终以掌心为稳定锚点，并映射到实际牌带的牌面中段，避免 OPEN 切换到 PINCH 时准星跳离目标。捏合使用画面二维距离主判、有效世界坐标辅助；OPEN 已命中的卡牌在过渡姿态或短暂丢手时会继续锁定约 520ms，牌间空隙另有 12px 命中滞回，减少合拢手指时的目标闪断。

## 流动牌带与空间背景

底部牌背以两组等宽轨道持续向左循环。接近左侧的窄幅侧视黑洞时，卡牌向洞心汇聚、折转并缩入纵深，最后通过遮罩完整消失；前后光子环与引力流随吸入过程增强。鼠标或触摸可以左右拖动牌带，松开后继续自动流动；拖动不会误触抽牌。

鼠标按下、触摸选取、键盘聚焦、OPEN / PINCH 命中及抓取预览等交互阶段会暂时控制牌带暂停，普通鼠标悬停不会打断移动。取消回程或确认销毁结束后恢复移动。界面没有独立的手动暂停按钮；`prefers-reduced-motion` 下关闭非必要的漂浮、吸入变形与视差，并减慢核心牌带循环。

`background.js` 使用 Canvas 2D 绘制远近两层的短促闪烁星粒、带前后半球明暗差的透视经纬球，以及两条反向倾斜的空间轨道。鼠标、触摸与摄像头手部移动会共同驱动带弹簧余摆的三轴旋转和深度视差；移动越快，球体晃动、近景星粒位移与亮度会短暂增强。页面隐藏时停止刷新，摄像头开启和移动端会自动降低曲线采样或帧率，减少动态效果模式只保留静态空间图层。

确认时会先取得卡牌的可见矩形；牌库移除与历史写入随后在同一轮同步提交，并且不会等待灰烬 Promise 完成。粒子或 WebGL 失败不会阻止下一张牌生成。

## 鼠标、触摸与键盘

| 意图 | 鼠标 / 触摸 | 键盘 |
| --- | --- | --- |
| 允许抽取 | 点击「进入待抽牌」；直接点击牌背也会自动允许并抓取 | `O`，或在状态按钮上按 `Enter` / `Space` |
| 浏览与指向 | 牌带自动向左；鼠标或触摸左右拖动浏览，轻触牌背抓取 | `←` / `→` 切换目标 |
| 抓取 | 点击或轻触牌背；已允许时也可点「抓取高亮牌」 | 聚焦牌背或状态按钮后按 `Enter` / `Space` |
| 确认 | 预览后点击「确认并锁定」 | 聚焦确认按钮后按 `Enter` / `Space` |
| 放回待确认牌 | 点击「放回牌库」 | `Esc` |
| 撤回最后结果 | 点击「撤回」 | `Ctrl + Z`；macOS 为 `Cmd + Z` |
| 开关摄像头 | 点击右上角摄像头按钮 | `G` |
| 开关声音 | 点击顶部声音按钮 | 聚焦声音按钮后按 `Enter` / `Space` |

长按产生的重复 `keydown` 会被忽略。鼠标与触摸不需要机械复刻 OPEN：直接点击牌背会一次完成「允许 + 抓取」，但仍必须在预览阶段单独确认。

## 音乐与历史记录

`audio.js` 使用 Web Audio 在浏览器内合成氛围音乐与确认音效，不依赖外部音频文件。受浏览器自动播放策略影响，声音在用户首次点击、触摸或按键后才能启动；顶部声音按钮可同时关闭音乐与音效，静音偏好保存在当前浏览器。正位与逆位使用不同的确认音序，切到后台时暂停声音。

「本轮已锁定结果」记录当前三张牌的牌名、正逆位和对应含义。完整确认三张后，牌阵的问题、确认时间及三张牌会保存到 `localStorage`；下一轮或重新打开同一站点时，可在「上次完整牌阵」查看最近一次完整结果。未完成的牌阵不会存为完整历史，当前轮撤回后也会撤销该轮的完整存档。记录仅属于当前浏览器与站点地址，清除浏览数据、更换浏览器、设备或域名后不会自动同步；浏览器禁用存储时仍可进行当前局抽牌。

## 卡牌图片来源

历史面板中的「卡牌图源」可以切换三种模式；选择会在浏览器允许时保存到 `localStorage`。

| 模式 | 加载顺序 |
| --- | --- |
| `自动：本地 → URL` | 优先加载 `assets/cards-webp/` 的 WebP，失败后尝试 `assets/cards/` 的 JPG，再回退至 Wikimedia URL；这是首次打开时的默认模式。 |
| `Wikimedia URL` | 只加载 Wikimedia Commons 的 960px 高清缩略图。 |
| `本地 assets/cards` | 依次尝试本地 WebP、JPG；均不可用时显示带牌名的占位卡，不请求远程牌面。 |

在线牌面使用同一套 Pam-A Rider–Waite–Smith 公版扫描：[Wikimedia Commons 图集](https://commons.wikimedia.org/wiki/Category:Rider-Waite-Smith_tarot_deck_(TaionWC))。网络、跨域或文件缺失不会卡住抽牌流程，最终会显示内置占位。

仓库已附带统一牌背 `assets/cards/back.svg`、完整 78 张 WebP 牌面及 78 张 960px 宽 JPG 回退图。两套牌面与牌背合计约 55 MiB。替换自己的本地牌面时，请同步更新 `assets/cards-webp/` 的同名 `.webp` 与 `assets/cards/` 的 `.jpg`，否则优先加载的 WebP 仍会显示旧图。文件名使用小写 ASCII 与两位数字：

- 大阿尔卡那：`major-00.jpg` 至 `major-21.jpg`
- 权杖：`wands-01.jpg` 至 `wands-14.jpg`
- 圣杯：`cups-01.jpg` 至 `cups-14.jpg`
- 宝剑：`swords-01.jpg` 至 `swords-14.jpg`
- 星币：`pentacles-01.jpg` 至 `pentacles-14.jpg`

详细约定也见 `assets/cards/README.md`。牌背始终使用项目内的 `back.svg`，不受图源模式影响。

## Three.js 灰烬效果

确认牌后，`ash.js` 按卡牌可见矩形区域采样 320–1600 个粒子，使用 Three.js `Points + BufferGeometry + ShaderMaterial` 单批绘制。每个粒子具有随机大小、初速度、延迟、寿命和透明度；顶点着色器令粒子向上飘动并叠加轻微湍流，透明度随寿命逐帧衰减。

- 通过 localhost 运行时，优先加载随项目提供的 `vendor/three.module.min.js`，失败后尝试 CDN。
- 直接双击时立即使用 CSS 灰烬降级；通过 HTTP 打开时才加载 Three.js 模块。
- WebGL 或 Three.js 不可用时降级为 CSS 灰化、上移与淡出。
- `prefers-reduced-motion: reduce` 下不执行位移、缩放或模糊动画，直接完成视觉切换。
- 每次效果结束都会从场景移除 Points，并释放 geometry 与 material；重置和离开页面也会主动清理。

## 文件结构

- `index.html`：页面结构、抽牌控制、历史面板与帮助对话框
- `styles.css`：主题、响应式布局、牌面方向和交互动效
- `deck.js`：78 张牌的数据、RWS 文件映射和图片候选地址
- `app.js`：抽牌状态机、随机与历史、键鼠触控、MediaPipe 手势识别
- `background.js`：响应指针与手势的粒子、透视经纬网和空间视差
- `ash.js`：Three.js 灰烬粒子及 CSS 降级
- `audio.js`：本地合成的氛围音乐、确认音效与静音偏好
- `vendor/three.module.min.js`、`vendor/three.core.min.js`：固定版本的本地 Three.js 模块
- `vendor/mediapipe/`：固定版本的 MediaPipe Vision、WASM 与 Hand Landmarker 模型
- `assets/cards/`：统一牌背与完整的本地 78 张 RWS JPG
- `assets/cards-webp/`：优先加载的完整 78 张 WebP 牌面
